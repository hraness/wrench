Telegram contacts · Wrench {{WRENCH_VERSION}}

Sync Telegram contacts through a private TDLib user session.

Wrench can read the current contact list of one Telegram user after explicit pairing. It uses Telegram’s official TDLib user-client API, stores an account-bound projection locally, and serves bounded pages without reconnecting during the read.

The provider does not use the Telegram Bot API, scan message history, or turn missing activity into zero.

What the Telegram provider reads

The telegram-linked-device provider calls TDLib getMe to bind the local store to one numeric Telegram user ID, then calls getContacts to refresh that account’s current contacts. The offline contacts.list operation returns numeric user ID, names, display name, active username, phone number, and mutual-contact, Premium, and verification flags when TDLib provides them.

TDLib getContacts does not return message history. Sent count, received count, last sent, and last received therefore remain null with the explicit reason tdlib-contacts-do-not-include-message-history. Wrench does not silently broaden a contact read into a conversation scan.

Inspect the release-bound operation, contract version, risk, and access method.

Why a Telegram bot token is not enough

A Telegram bot is a separate account with bot-scoped updates. It cannot authorize access to a human user’s contact list. Wrench therefore accepts only an explicitly paired TDLib user session for this operation and never substitutes the Bot API when that session is missing or invalid.

1. Install the pinned TDLib helper

The package ships a small native helper source and build recipe pinned to TDLib 1.8.67 at commit d1085f9cebc5a62379991ae1652673954f229c1f. The runtime executes only the installed helper whose manifest, bytes, embedded identity, owner, mode, links, size, and file identity pass verification.

wrench doctor --json
# Run the reported Telegram setupCommand, then verify:
wrench doctor

A packaged installation reports the exact checked installer path in setupCommand. From an exact Wrench source checkout, run bun run telegram:tdlib:install. The source build supports macOS and Linux on arm64 and x64 and requires Git, CMake, Make, gperf, a C++17 compiler, OpenSSL, zlib, and system threads. Wrench does not load TDLib into Bun or search PATH for an alternate runtime helper.

2. Pair one Telegram user

Create a dedicated mode-0700 store and a mode-0600 client.conf containing the api_id and lowercase api_hash for an application registered at my.telegram.org. Keep the API hash, login codes, two-step-verification password, and TDLib state out of Git and agent transcripts.

wrench adapter sync-bundled --json
wrench auth add telegram-main --linked-device telegram \
  --device-store /absolute/private/telegram-main
wrench auth pair telegram-main --phone +15551234567

The helper handles the reviewed existing-user authorization states through its controlling terminal. Registration, bot-token authorization, and unknown states fail closed. A successful pair publishes contacts.v1.json and binds the auth realm to telegram:user:<numeric-user-id>.

3. Refresh deliberately, then read offline

Pairing and one-shot sync are the only Telegram-network steps. The contact read uses the last validated local projection.

wrench auth sync telegram-main --once --json
wrench telegram contacts.list --auth telegram-main \
  --input '{"limit":50}' --json

Results are ordered by numeric Telegram user ID. Pass the returned nextCursor back as cursor to continue, with a page limit from 1 through 200. Sync refuses to replace the projection if TDLib returns a different user from the bound account.

Local custody and revocation

The private store contains the client configuration, TDLib database and files, and Wrench’s contact projection. Removing a Wrench auth locator does not revoke Telegram’s provider-side session. Revoke the linked device separately in Telegram when access should end.

Interrupted pair or sync work remains durably fenced because those operations can emit protocol acknowledgements. Inspect recovery state with wrench operator doctor --json; do not retry an uncertain lifecycle by deleting its journal.
